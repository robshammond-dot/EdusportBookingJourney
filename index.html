01Where This Stands

Current state, not target state

This is a full pre-travel and post-travel mailer series, drafted as email copy across four booking-to-travel windows: Long (9–12 months out), Medium (6–3 months out), Short (3–1 months out), and Post-Travel. It has not been built as a live journey yet. Nicky's feedback below is the open input this needs before it moves to build.

02Open Questions from Nicky

Carried forward from her review, still needing a decision

RaisedWhat it means for this build
Volume of mailers 10 mailers before travel in the Long window may be too many, especially since customers are also communicating directly with their consultant. Worth looking at consolidating content rather than cutting touchpoints blind, see Mailer Volume, At a Glance below.
Destination-specific content Several mailers reference visa requirements, local highlights, cuisine, and event venues, populated per destination. Need to confirm whether this level of destination detail is available from current booking data, or whether it has to be manually maintained per event/destination.
Infographics / attachments Journeys can't carry file attachments, that's only possible in a bulk mailer email template. Where an infographic is genuinely wanted, the options are: build it directly into the email as an image, or host it online and link to it from the journey.
Rollout scope Agreed starting point: one event first, then expand once proven. Which event that is still needs confirming.
Journey vs Sequence Open question on the right build mechanism, a Freshmarketer Journey with designed mailers, or a Freshsales Sequence with email templates. Worth a short working session comparing the two before committing either way.

08Things Worth Deciding Together

The Fresh build itself sits with Robyn; these are the calls that shape the content and structure first

Duration matters for window choice Classic Sequences are capped at 90 days total. Smart Sequences run on repeating intervals rather than a fixed date. Neither is built for something spanning up to 12 months, so whatever the Long window ends up running on is a different shape of tool to whatever the Medium and Short windows run on. Worth knowing this before locking in content cadence, not a decision to make here.

What Fresh reliably knows about a booking

Event Name is a multiselect field, so it doesn't get overwritten, older events stay in the list, but it stops being the primary or most obvious one to read off once a new enquiry comes in. Travel Date does get genuinely overwritten, along with the customer status, whenever a new enquiry arrives, that's deliberate, handled by workflows, and exists to keep active quoting and status correct for whatever the customer's current enquiry actually is, not an oversight. The practical effect for this series is the same either way: whatever timing mechanism gets built needs its own way of anchoring to the right trip, rather than assuming the live Contact fields will always point at it.

Destination content is static, not synced

Event → Destination is a fixed lookup the team already knows, not data missing from Fresh. Rather than treating it as something to sync, write it once per event, directly into that event's content. This only works cleanly for Tier 1 evergreen events (see event tiering above), which is exactly why the pilot should start there.

Cancellations are already distinguishable

Cancellation is captured as a Lost Reason on the Enquiry, so a cancelled-after-Won customer can be told apart from a pre-booking Lost. One traveller dropping out of a group booking isn't an issue in itself, fine for the rest of the party to keep receiving the series. What does need handling is the whole booking cancelling after the group was already added to the event segment, that needs a way to remove them from it so the series stops.

Open product question, not yet decided What happens when a repeat traveller books a genuinely second, separate trip while their first Booking Journey is still running? A second, parallel journey, or excluded while the first is active?
